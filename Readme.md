# 📊 Dynamic Asset Allocation using Deep Reinforcement Learning

> A Deep Reinforcement Learning framework for dynamically allocating capital across multiple assets while balancing return and risk.

## 📌 Overview

Traditional portfolio management often uses fixed weights or manually defined rebalancing rules. Financial markets are dynamic: returns, volatility, correlations, and risk change over time.

This project formulates portfolio management as a **Markov Decision Process (MDP)** and uses **Deep Deterministic Policy Gradient (DDPG)** to learn a continuous portfolio-allocation policy.

The central mapping is:

```math
\pi_\theta : s_t \rightarrow a_t
```

where:

- $s_t$ = market state at time $t$
- $a_t$ = continuous action generated by the Actor
- $\theta$ = Actor-network parameters

The action is converted into portfolio weights, and the resulting portfolio return is used to calculate the reward.

---

# 🎯 Problem Formulation

Assume the portfolio contains $N$ assets. The allocation vector at time $t$ is

```math
\mathbf{w}_t = [w_{1,t},w_{2,t},\ldots,w_{N,t}]^T
```

For a long-only, fully invested portfolio:

```math
\sum_{i=1}^{N}w_{i,t}=1
```

```math
0\leq w_{i,t}\leq1
```

The objective is to learn a policy that maximizes long-term risk-adjusted portfolio performance:

```math
\pi^* = \arg\max_{\pi} \mathbb{E}_{\pi}\left[\sum_{t=0}^{T-1}\gamma^t r_t\right]
```

where $\gamma$ is the discount factor and $r_t$ is the portfolio reward.

---

# 🧠 1. Markov Decision Process

Portfolio allocation can be represented as

```math
\mathcal{M}=(S,A,P,R,\gamma)
```

where:

- $S$ = state space
- $A$ = continuous action space
- $P(s_{t+1}|s_t,a_t)$ = transition dynamics
- $R(s_t,a_t)$ = reward function
- $\gamma\in[0,1]$ = discount factor

At every step:

```math
s_t \rightarrow a_t \rightarrow r_t \rightarrow s_{t+1}
```

The agent therefore learns a **sequence of portfolio decisions**, rather than simply predicting the next stock price.

# 📅 4. Historical Data

For asset $i$, let the closing-price series be

```math
P_{i,t}, \qquad t=1,2,\ldots,T
```

The data may contain:

- Date
- Open
- High
- Low
- Close
- Volume

The workflow checks missing observations and aligns assets to a common usable date range before training.

---

# 🧹 5. Data Cleaning and Common Date Range

Different assets may have different listing dates, holidays, missing observations, or incomplete histories.

The multi-asset price matrix is represented as

```math
\mathbf{P}=\begin{bmatrix}
P_{1,1} & P_{2,1} & \cdots & P_{N,1}\\
P_{1,2} & P_{2,2} & \cdots & P_{N,2}\\
\vdots & \vdots & \ddots & \vdots\\
P_{1,T} & P_{2,T} & \cdots & P_{N,T}
\end{bmatrix}
```

Before training, missing values should be handled so that NaNs do not propagate into the state, reward, or neural-network updates.

---

# 📈 6. Return Calculation

For a close-to-close simple return:

```math
R_{i,t}=\frac{P_{i,t}-P_{i,t-1}}{P_{i,t-1}}
```

Percentage return:

```math
R_{i,t}^{(\%)}=\frac{P_{i,t}-P_{i,t-1}}{P_{i,t-1}}\times100
```

For an open-to-close return:

```math
R_{i,t}^{OC}=\frac{C_{i,t}-O_{i,t}}{O_{i,t}}\times100
```

The return vector across all assets is

```math
\mathbf{r}_t=[R_{1,t},R_{2,t},\ldots,R_{N,t}]^T
```

---

# 📊 7. Mean Return and Volatility

For asset $i$, historical mean return is

```math
\mu_i=\frac{1}{T}\sum_{t=1}^{T}R_{i,t}
```

The mean-return vector is

```math
\boldsymbol{\mu}=[\mu_1,\mu_2,\ldots,\mu_N]^T
```

Historical sample volatility is

```math
\sigma_i=\sqrt{\frac{1}{T-1}\sum_{t=1}^{T}(R_{i,t}-\mu_i)^2}
```

and the volatility vector is

```math
\boldsymbol{\sigma}=[\sigma_1,\sigma_2,\ldots,\sigma_N]^T
```

---

# 🔗 8. Covariance and Portfolio Risk

Let $\Sigma$ denote the covariance matrix:

```math
\Sigma_{ij}=\operatorname{Cov}(R_i,R_j)
```

For portfolio weights $\mathbf{w}_t$, portfolio variance is

```math
\sigma_{p,t}^2=\mathbf{w}_t^T\Sigma_t\mathbf{w}_t
```

and portfolio volatility is

```math
\sigma_{p,t}=\sqrt{\mathbf{w}_t^T\Sigma_t\mathbf{w}_t}
```

This shows why diversification matters: portfolio risk depends on both individual asset volatility and cross-asset covariance.

---

# 📐 9. Min-Max Normalization

To put features on a comparable scale, Min-Max normalization can be used.

For a feature $x$:

```math
\tilde{x}=\frac{x-x_{\min}}{x_{\max}-x_{\min}}
```

Therefore:

```math
0\leq\tilde{x}\leq1
```

**Important:** scaling parameters should be fitted using training data and then applied to validation/test data. Calculating scaling statistics from the complete dataset can introduce look-ahead leakage.

---

# 🏦 10. Custom Portfolio Trading Environment

The environment converts portfolio management into an RL problem.

At time $t$:

1. Observe state $s_t$.
2. Actor generates action $a_t$.
3. Convert action into portfolio weights $\mathbf{w}_t$.
4. Observe next-period asset returns.
5. Calculate portfolio return.
6. Calculate reward $r_t$.
7. Move to $s_{t+1}$.

The resulting transition is

```math
(s_t,a_t,r_t,s_{t+1})
```

---

# 🧩 11. State Space

The state represents information available at decision time.

Conceptually:

```math
s_t=[\text{normalized market features},\text{asset returns},\text{risk features},\text{portfolio information}]
```

The critical financial-ML requirement is that $s_t$ must not contain information from the future.

Using future prices, future returns, or future-derived statistics when constructing $s_t$ creates **look-ahead bias**.

---

# 🎮 12. Continuous Action Space

The Actor produces a continuous action vector:

```math
\mathbf{a}_t=[a_{1,t},a_{2,t},\ldots,a_{N,t}]
```

The action is transformed into portfolio weights.

One possible normalization is:

```math
w_{i,t}=\frac{\max(a_{i,t},0)}{\sum_{j=1}^{N}\max(a_{j,t},0)}
```

An alternative is a Softmax output:

```math
w_{i,t}=\frac{e^{z_{i,t}}}{\sum_{j=1}^{N}e^{z_{j,t}}}
```

which guarantees

```math
0<w_{i,t}<1
```

and

```math
\sum_{i=1}^{N}w_{i,t}=1
```

---

# 💰 13. Portfolio Return

Once the allocation is selected, the next-period portfolio return is

```math
R_{p,t+1}=\sum_{i=1}^{N}w_{i,t}R_{i,t+1}
```

or equivalently

```math
R_{p,t+1}=\mathbf{w}_t^T\mathbf{r}_{t+1}
```

If $V_t$ is portfolio value:

```math
V_{t+1}=V_t(1+R_{p,t+1})
```

Starting from $V_0$:

```math
V_T=V_0\prod_{t=0}^{T-1}(1+R_{p,t+1})
```

Cumulative return is

```math
CR=\frac{V_T}{V_0}-1
```

---

# 🏆 14. Reward Function

A simple reward based only on return is

```math
r_t=R_{p,t+1}
```

A risk-penalized objective can be written as

```math
r_t=R_{p,t+1}-\lambda\sigma_{p,t+1}^2
```

where $\lambda\geq0$ controls risk aversion.

A Sharpe-like reward can be represented as

```math
r_t=\frac{E[R_p]-R_f}{\sigma_p+\epsilon}
```

where $R_f$ is the risk-free return and $\epsilon$ prevents division by zero.

The reward should be consistent with the actual implementation used by the environment.

---

# 🧠 15. DDPG Architecture

The project uses **Deep Deterministic Policy Gradient (DDPG)** for continuous portfolio allocation.

DDPG uses four networks:

1. Actor network
2. Critic network
3. Target Actor network
4. Target Critic network

The architecture is:

```text
                 State s_t
                    │
                    ▼
             ┌─────────────┐
             │    Actor    │
             │ μθ(s_t)     │
             └──────┬──────┘
                    │
                    ▼
              Action a_t
                    │
                    ▼
             Portfolio Weights
                    │
                    ▼
             ┌─────────────┐
State s_t ──►│   Critic    │◄── Action a_t
             │ Qφ(s_t,a_t) │
             └─────────────┘
```

---

# 🎯 16. Actor Network

The Actor represents the deterministic policy:

```math
\mathbf{a}_t=\mu_\theta(s_t)
```

The Actor is trained to choose actions that maximize the Critic's estimated value.

The deterministic policy gradient is

```math
\nabla_\theta J(\theta)\approx\frac{1}{B}\sum_{i=1}^{B}\left[\nabla_aQ_\phi(s,a)\big|_{a=\mu_\theta(s_i)}\nabla_\theta\mu_\theta(s_i)\right]
```

Here $B$ is the mini-batch size.

---

# 🧪 17. Critic Network

The Critic estimates the value of a state-action pair:

```math
Q_\phi(s_t,a_t)
```

The action-value function is

```math
Q^\pi(s_t,a_t)=\mathbb{E}_\pi\left[\sum_{k=0}^{\infty}\gamma^k r_{t+k}\mid s_t,a_t\right]
```

The Critic therefore answers:

> **How valuable is this portfolio allocation, given the current market state?**

---

# 🔁 18. Bellman Target

For a transition $(s_i,a_i,r_i,s_{i+1},d_i)$, the DDPG target is

```math
y_i=r_i+\gamma(1-d_i)Q_{\phi'}\left(s_{i+1},\mu_{\theta'}(s_{i+1})\right)
```

where:

- $\theta'$ = target Actor parameters
- $\phi'$ = target Critic parameters
- $d_i$ = terminal indicator

The Critic minimizes the mean-squared Bellman error:

```math
L_{\mathrm{Critic}}(\phi)=\frac{1}{B}\sum_{i=1}^{B}\left(Q_\phi(s_i,a_i)-y_i\right)^2
```

---

# 📉 19. Actor Loss

The Actor attempts to maximize the Critic's estimated Q-value.

Therefore its loss can be written as

```math
L_{\mathrm{Actor}}(\theta)=-\frac{1}{B}\sum_{i=1}^{B}Q_\phi\left(s_i,\mu_\theta(s_i)\right)
```

This is the equation that should be displayed as **Actor Loss**. `Sharpe`, `Critic`, or other text should never be placed inside this mathematical block.

---

# 💾 20. Experience Replay

Transitions are stored in a replay buffer:

```math
\mathcal{D}=\{(s_t,a_t,r_t,s_{t+1},d_t)\}
```

A mini-batch is randomly sampled:

```math
\mathcal{B}\sim\mathcal{D}
```

This reduces temporal correlation between consecutive observations and improves training stability.

Conceptually:

```python
transition = (state, action, reward, next_state, done)
replay_buffer.append(transition)
batch = replay_buffer.sample(batch_size)
```

---

# 🎲 21. Exploration Noise

Because the DDPG Actor is deterministic, exploration noise is added during training:

```math
a_t=\mu_\theta(s_t)+\epsilon_t
```

For Gaussian exploration:

```math
\epsilon_t\sim\mathcal{N}(0,\sigma^2I)
```

The noise magnitude can be reduced during training so the agent gradually moves from exploration toward exploitation.

---

# 🎯 22. Target Networks

DDPG uses slowly updated target networks.

The target Actor is updated as

```math
\theta'\leftarrow\tau\theta+(1-\tau)\theta'
```

and the target Critic as

```math
\phi'\leftarrow\tau\phi+(1-\tau)\phi'
```

where $\tau$ is a small positive value.

These soft updates make the Bellman target more stable during training.

---

# 🔄 23. Daily Dynamic Allocation

The complete decision cycle is

```math
s_t\xrightarrow{\text{Actor}}a_t\xrightarrow{\text{allocation transform}}\mathbf{w}_t\xrightarrow{\text{market return}}R_{p,t+1}\xrightarrow{\text{reward}}r_t
```

Because the Actor receives a new state every period, portfolio weights can change dynamically.

For example:

```text
Day t:
Asset 1 = 10%
Asset 2 = 25%
Asset 3 = 05%
Asset 4 = 35%
Asset 5 = 25%

Day t+1:
Asset 1 = 18%
Asset 2 = 12%
Asset 3 = 20%
Asset 4 = 30%
Asset 5 = 20%
```

The actual allocations are learned by the policy.

# 📏 25. Performance Metrics

## Cumulative Return

```math
CR=\frac{V_T-V_0}{V_0}
```

## CAGR

For $Y$ years:

```math
CAGR=\left(\frac{V_T}{V_0}\right)^{1/Y}-1
```

## Annualized Volatility

For daily volatility $\sigma_d$ and $M$ trading days per year:

```math
\sigma_{annual}=\sigma_d\sqrt{M}
```

## Sharpe Ratio

```math
\mathrm{Sharpe}=\frac{E[R_p]-R_f}{\sigma_p}
```

For daily returns with annualization:

```math
\mathrm{Sharpe}_{annual}=\frac{E[R_d]-R_{f,d}}{\sigma_d}\sqrt{M}
```

## Sortino Ratio

```math
\mathrm{Sortino}=\frac{E[R_p]-R_f}{\sigma_{down}}
```

## Maximum Drawdown

Running peak portfolio value:

```math
Peak_t=\max_{u\leq t}V_u
```

Drawdown:

```math
DD_t=\frac{V_t}{Peak_t}-1
```

Maximum drawdown:

```math
MDD=\min_t DD_t
```

# 📉 26. Nifty 50 Benchmark

The strategy is compared with the **Nifty 50** to evaluate whether the learned portfolio provides attractive performance relative to a passive market benchmark.

A CAPM-style regression is

```math
R_p-R_f=\alpha+\beta(R_m-R_f)+\epsilon
```

where:

- $R_p$ = portfolio return
- $R_m$ = benchmark return
- $R_f$ = risk-free return
- $\alpha$ = benchmark-adjusted excess return
- $\beta$ = sensitivity to benchmark movements

Beta is calculated as

```math
\beta=\frac{\operatorname{Cov}(R_p,R_m)}{\operatorname{Var}(R_m)}
```

# ⚠️ 29. Quantitative Finance Considerations

## Look-Ahead Bias

State $s_t$ must only contain information available at time $t$.

## Survivorship Bias

A backtest using only assets that survived until today can overestimate historical performance.

## Transaction Costs

Frequent rebalancing creates turnover. A more realistic net return can include transaction costs:

```math
R_{net,t+1}=R_{p,t+1}-c\cdot Turnover_t
```

where

```math
Turnover_t=\sum_{i=1}^{N}|w_{i,t}-w_{i,t-1}|
```

## Slippage

Historical close prices do not necessarily represent executable prices. Realistic backtests should consider market impact and slippage.

## Overfitting

DRL models have high flexibility and can overfit historical regimes. Walk-forward validation and multiple market regimes are recommended.

## Data Leakage

Preprocessing must be fitted only on information available during training.

# 📐 31. Complete Mathematical Formulation

The complete problem can be summarized as follows.

### State

```math
s_t=f(\text{market history up to }t,\text{portfolio history up to }t)
```

### Action

```math
a_t=\mu_\theta(s_t)
```

### Portfolio Weights

```math
\mathbf{w}_t=g(a_t)
```

subject to

```math
\mathbf{1}^T\mathbf{w}_t=1,\qquad \mathbf{w}_t\geq0
```

### Portfolio Return

```math
R_{p,t+1}=\mathbf{w}_t^T\mathbf{r}_{t+1}
```

### Portfolio Value

```math
V_{t+1}=V_t(1+R_{p,t+1})
```

### Portfolio Risk

```math
\sigma_{p,t}^2=\mathbf{w}_t^T\Sigma_t\mathbf{w}_t
```

### Reward

```math
r_t=U(R_{p,t+1},\sigma_{p,t+1},Turnover_t,Drawdown_t)
```

### RL Objective

```math
\pi^*=\arg\max_\pi\mathbb{E}_\pi\left[\sum_{t=0}^{T-1}\gamma^tr_t\right]
```

Thus, the project learns a **policy over portfolio allocations**, rather than simply predicting future asset prices.

# 🎓 35. Key Takeaway

The central idea is:

> **The model does not simply ask which asset will perform best tomorrow. It learns how the entire portfolio should be reallocated today based on the current market state.**

The complete learning loop is:

```math
\boxed{
\text{Market State}
\rightarrow
\text{Allocation}
\rightarrow
\text{Portfolio Return}
\rightarrow
\text{Reward}
\rightarrow
\text{Policy Update}
}
```

This turns portfolio management into a **continuous sequential optimization problem**.
